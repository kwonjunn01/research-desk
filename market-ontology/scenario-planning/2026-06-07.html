Weekly Scenario Planning — 2026-06-07

투자 추천이 아니다. 공개 정보와 Research Desk 수집 자료를 바탕으로, 이번 주의 기술/시장 내러티브가 어떤 병목과 검증 질문으로 이어지는지 기록한 관찰 보고서다. 개별 투자 행동 판단, 매수/매도 추천, 가격목표, 확정 수익률을 제시하지 않는다.

0. 이번 주 한줄 결론

이번 주 base case는 “Agent와 Physical AI 신호는 계속 강해지지만, 1~2년 승부처는 더 큰 모델 발표가 아니라 stateful agent runtime·eval/security, long-context/KV/RAG 비용, HBM·advanced packaging·inspection, rack power·cooling·grid, optical/networking 병목을 실제로 줄이는 계층으로 좁혀지는 경로”다. 시장은 Robotics, HBM, AI Semiconductor, Power Infrastructure, Cloud Hyperscaler를 번갈아 상단에 올렸지만, 아직 결론은 “수혜주”가 아니라 capex가 실제 workload·capacity·backlog·qualification·revision으로 전환되는지 확인해야 하는 병목 지도다.

1. 이번 주 가장 그럴듯한 시나리오

이번 주도 회사부터 보지 않았다. 먼저 최근 1주일의 AI research, market narrative, semiconductor/HBM/packaging, power/grid/cooling, optical/networking, agent software/runtime/eval/security, robotics/on-device, geopolitics/export-control 신호를 원인 → 전파 경로 → 병목 → 수혜/피해 레이어 → 검증 질문으로 묶었다.

Base scenario는 agent와 robotics/on-device가 “실사용 표면”을 넓히지만, 바로 완전 자동화나 폭발적 양산으로 가지는 않는 경로다. AI Research Radar에서 2026-06-01~06-07 동안 Agentic AI와 Agent Evaluation이 반복 상단에 올라왔고, Where Do Deep-Research Agents Go Wrong?, RAMP, Agent libOS, BraveGuard, AdaPlanBench, TIDE, ArcANE 같은 신호가 같은 방향을 가리켰다. 핵심은 “agent가 똑똑해졌다”가 아니라 긴 작업을 계획하고, 실패 위치를 찾고, 권한을 제한하고, memory/policy/persona 변화를 추적하며, 실제 tool/browser/OS 환경에서 복구할 수 있는가다.

이 base에서는 post-training과 reasoning도 단순 compute 절감 재료가 아니다. Trust Region On-Policy Distillation, reward hacking 분석, VideoKR, Reinforcement Learning Elicits Contextual Learning 같은 신호는 “보상·검증·일반화”가 병목임을 보여준다. 모델이 더 유용해지면 오히려 agent session, tool call, retrieval, replay, eval, observability가 늘 수 있다. 그래서 base case에서는 효율화와 workload 증가가 동시에 존재한다.

동시에 inference와 memory 신호가 더 선명해졌다. Code2LoRA는 repository-level context를 매번 긴 입력/RAG/fine-tuning으로 처리하는 비용을 줄이려는 시도이고, KVarN, OCC-RAG, Value-Aware KV eviction류 신호는 KV cache, RAG faithfulness, local retrieval, long-context 비용이 실제 운영 병목임을 말한다. 이 병목은 software stack에서 시작하지만 server memory, HBM/DRAM bandwidth, AI server bill-of-material, power/cooling으로 전파된다.

시장 쪽 base는 AI capex가 계속되되, ROI와 물리 인프라가 투자 속도를 필터링하는 경로다. 2026-06-01~06-05 Market Brief에서 Robotics, HBM Memory, AI Semiconductor, Power Infrastructure, Cloud Hyperscaler가 반복 상위 theme으로 잡혔다. 06-01은 Robotics 36·HBM 34, 06-02는 AI Semiconductor·HBM·Robotics가 29, 06-03은 Robotics 30·AI Semiconductor 29·HBM 27, 06-04는 Robotics 31·HBM/Power 30, 06-05는 Cloud Hyperscaler·Robotics 30과 AI Semiconductor 29가 상단이었다. 중요한 점은 매일 다른 종목이 아니라 cloud capex → AI data center → semiconductor/HBM → power/grid/cooling → robotics/on-device라는 같은 전파 경로가 반복됐다는 것이다.

Upside scenario는 agent runtime/eval/security가 예상보다 빨리 제품 gate로 흡수되고, robotics/on-device가 field deployment와 반복 주문으로 확인되는 경로다. 이 경우 AdaPlanBench, TIDE, Agent libOS, BraveGuard, RobotValues, Dream.exe 같은 연구 신호가 benchmark attention에서 끝나지 않고 enterprise workflow, developer toolchain, personal assistant, industrial automation, humanoid/edge device stack으로 내려온다. 그러면 cloud inference session과 edge inference가 동시에 늘고, HBM/advanced packaging, power/cooling, optical/networking, agent observability/security까지 demand chain이 넓어진다. 이때도 company tier는 가격 움직임이 아니라 product release note, paid deployment, backlog, qualification, yield/throughput, verified revision evidence가 붙을 때만 올라간다.

Downside scenario는 capex ROI 의심과 agent/robotics 신뢰성 문제가 동시에 커지는 경로다. Hyperscaler와 neocloud가 큰 capex를 유지해도 utilization, AI revenue contribution, inference margin, capacity booking이 약하면 시장은 AI capex 피로로 이동한다. Agent는 reward hacking, memory poisoning, RAG provenance, permission boundary, GUI/browser long-tail failure, security incident를 넘지 못하면 paid workflow로 가지 못한다. Robotics/on-device는 demo와 headline은 많아도 반복 주문·안전 인증·maintenance economics가 없으면 narrative beta로 남는다. Export-control은 이번 주 local report에서는 직접 신호가 약했지만, 중국 robotics, sovereign AI, energy geography, data-center siting은 지역별 supply-chain 분절 가능성을 남겼다.

가장 그럴듯한 중심축은 Base scenario다. 이유는 이번 주 신호가 “강한 성장”이나 “AI 버블 붕괴” 한쪽으로 정렬된 것이 아니라, workload와 capex는 계속 확장되지만 adoption·ROI·HBM/packaging·전력/냉각·runtime/security가 동시에 gate로 남는 구조로 정렬됐기 때문이다.

2. 왜 이 시나리오가 base case인가

첫째, research signal이 agent의 “실사용 실패 지점”으로 이동했다. 이번 주 HF Daily와 AI Research Radar는 Agentic AI, Agent Evaluation, On-device LLM, Inference Stack을 반복해서 상단에 올렸다. 특히 Where Do Deep-Research Agents Go Wrong?은 agent trajectory에서 span-level error를 찾으려 하고, AdaPlanBench는 world/user constraint가 점진적으로 드러나는 상황에서 adaptive planning을 평가한다. TIDE는 사용자가 명시하지 않은 hidden problem discovery를 다루고, Agent libOS와 BraveGuard는 agent가 실제 runtime과 security boundary를 필요로 한다는 쪽에 가깝다. 이것은 “agent demo가 많다”가 아니라 agent가 오래 일할 때 어디서 깨지는지 측정하려는 연구가 늘었다는 뜻이다.

둘째, RAG/memory/security는 enterprise adoption의 숨은 제약으로 남아 있다. 2026-06-04 Cross-Ontology Synthesis는 retrieval_trust_risk_controls_enterprise_adoption을 edge_strength 4/5, recognition_gap 5/5로 표시했다. OCC-RAG, MemTrain, M^3Eval, ClawMem, MCP-Persona, SkillHarm 같은 신호는 memory와 retrieval이 성능 개선 수단인 동시에 보안·provenance·governance risk임을 보여준다. 실제 구매 전환은 “RAG가 좋아졌다”가 아니라 audit log, source attribution, permission boundary, compliance, red-team 결과가 붙을 때 생긴다.

셋째, inference/KV/memory는 agent adoption의 비용 전파 경로다. Code2LoRA는 repository-level context를 긴 입력이나 매번 fine-tuning으로 해결하는 비용을 줄이려 한다. KVarN과 Value-Aware KV eviction은 reasoning task에서 KV cache 압축·오차 누적을 다룬다. RobotValues, Dream.exe, Cosmos 3, VideoKR 같은 physical/multimodal 신호는 text-only agent보다 더 큰 streaming memory와 latency 제약을 만든다. 이 신호가 실제 제품으로 가면 cloud serving p95 latency, VRAM, HBM/DRAM, storage/cache traffic, power/cooling으로 내려간다.

넷째, market narrative는 같은 chain의 물리 하단을 반복해서 건드렸다. 06-01 Market Brief는 Nvidia-Unitree/Reuters와 Samsung HBM4E/Micron 관련 신호를, 06-02는 AI Semiconductor·HBM·Robotics와 SMR/전력·DC EPC/부지 신호를, 06-03은 SK hynix/Nikkei·HBM shortage와 Supermicro rack-scale AI platform을, 06-04는 Bloomberg AI CapEx Rush, HBM bottleneck, liquid cooling, NC nuclear/data-center bill을, 06-05는 Cloud Hyperscaler capex와 power/cooling/grid를 상단에 두었다. 일부 출처는 보조/저신뢰로 표시되어 있어 결론 근거로 과대평가하면 안 되지만, 반복되는 node가 HBM·packaging·power·cooling·capex ROI에 몰린다는 점은 base scenario를 지지한다.

다섯째, power/cooling/grid는 단순 전력 테마가 아니라 capacity conversion gate다. SoftBank의 프랑스 AI data center/nuclear grid 언급, liquid cooling 기사, NC data center/nuclear bill, Europe AI power test, hyperscaler capex 논쟁은 모두 같은 질문으로 귀결된다. AI capex가 MW/GW 전력, transformer·switchgear, liquid cooling, site permitting, grid interconnect, PPA, backlog로 전환되는가? 전력 narrative가 이미 알려져 있다는 점은 오히려 tier 판단을 더 엄격하게 만든다. 반복 headline만으로는 부족하고 수주잔고·납기·마진·고객 계약이 필요하다.

여섯째, HBM/advanced packaging은 풀린 병목이 아니라 다시 좁아질 수 있는 병목으로 남아 있다. Market Brief는 HBM stack height, bandwidth, qualification, TSV/yield, supply allocation을 핵심 병목으로 반복 표시했다. Scientific American의 HBM bottleneck 기사, SK hynix HBM leadership/Nikkei, Samsung HBM4E sample shipment, Micron AI memory deal 신호는 모두 같은 축에 있다. 다만 공급 증설과 효율화가 동시에 일어나므로 “HBM이면 모두 수혜”가 아니라 qualification, yield, customer allocation, ASP/bit shipment, CoWoS/advanced packaging capacity, test/socket/metrology throughput을 따로 확인해야 한다.

일곱째, robotics/on-device는 base의 중심이라기보다 base를 강화하는 upside surface다. Market Brief는 06-01~06-05 동안 Robotics를 계속 상위 theme으로 잡았고, Reuters/CNBC/NVIDIA Newsroom 기반의 Unitree/Isaac GR00T/휴머노이드 신호가 반복됐다. AI Research 쪽에서도 RobotValues, Dream.exe, World-Language-Action Model, HANDOFF, Cosmos 3가 나왔다. 그러나 demo와 benchmark만으로는 부족하다. Field deployment, 반복 주문, safety certification, edge AI chip attach, sensor/actuator supply chain, maintenance economics가 확인되어야 Tier가 올라간다.

3. 이 시나리오가 만드는 병목 3~5개

첫 번째 병목은 stateful agent runtime·memory·eval/security gate다. Agent가 실제 개인 비서나 업무 자동화로 쓰이려면 긴 작업 상태를 유지하고, tool call과 browser/OS 행동을 기록하며, 실패 지점을 되짚고, 사용자 권한과 데이터 접근을 제한해야 한다. 이번 주 연구 신호는 바로 이 gate를 건드렸다. AdaPlanBench는 현실 문제에서 제약 조건이 뒤늦게 드러나는 상황을 다루고, Where Do Deep-Research Agents Go Wrong?은 agent trajectory의 실패 위치를 찾으려 하며, BraveGuard와 SkillHarm은 agent harness와 skill 설치의 보안 문제를 드러낸다. 깨는 기술은 stateful serving, agent trace/replay, sandboxed tool runtime, permissioned MCP, eval harness, RAG provenance, memory governance다. Timing window는 6~18개월이다. 시장이 아직 과소 반영한 부분은 “agent가 더 똑똑하다”보다 agent 운영체제와 control plane이 제품 gate로 들어갈지다.

두 번째 병목은 long-context/KV/RAG 비용과 memory bandwidth다. Agent와 coding assistant가 repo-level context, tool logs, retrieval, multimodal evidence를 오래 들고 가면 비용은 token 수만으로 설명되지 않는다. KV cache, prefill latency, retrieval quality, local memory, adapter generation, batch/routing, server memory가 함께 병목이 된다. Code2LoRA, KVarN, OCC-RAG, Value-Aware KV eviction, VideoMLA류 신호는 모두 이 비용을 줄이려는 시도다. 깨는 기술은 KV cache quantization/eviction, sparse attention, PEFT/hypernetwork adapter, retrieval compression, server-side memory hierarchy, inference scheduler다. Timing window는 3~12개월로 더 짧다. 다만 효율화가 총 capex를 줄일 수도 있고, 더 많은 agent session을 가능하게 해 총 workload를 키울 수도 있다. 그래서 확인 질문은 “비용 절감 논문이 나왔는가”가 아니라 production p95 latency, VRAM, token cost, serving margin, HBM/server memory pressure가 실제로 줄었는가다.

세 번째 병목은 HBM bandwidth와 advanced packaging/CoWoS/inspection capacity다. AI accelerator는 compute die만으로 출하되지 않는다. HBM3E/HBM4 qualification, stack yield, TSV, bonding, CoWoS/interposer, substrate, test socket, package inspection/metrology가 함께 맞아야 한다. 이 병목을 깨는 기술은 hybrid bonding, Cu-to-Cu bonding, advanced packaging metrology, hybrid bonding inspection, high-density test/socket, glass substrate, panel-level packaging이다. Timing window는 6~24개월이다. 이미 시장에 많이 알려진 병목이므로 단순 headline은 edge가 약하다. 진짜 검증은 고객 qualification, yield/throughput, capacity expansion, lead time, bit shipment, ASP, EPS/OP revision이 같은 방향으로 붙는지다.

네 번째 병목은 rack power delivery·cooling·grid interconnect·site permitting이다. AI data center capex가 계속되어도 전력·냉각·부지·계통 접속이 따라오지 않으면 capacity는 늦어진다. 1MW+ rack density, 48V/vertical power delivery, liquid cooling, transformer/switchgear, utility interconnect, PPA, permitting이 모두 gate가 된다. 깨는 기술은 48V direct conversion, vertical power delivery, high-density power module, liquid cooling integration, grid automation, transformer/switchgear capacity, data-center EPC execution이다. Timing window는 12~36개월로 길고 inertia가 강하다. 시장은 전력 narrative를 이미 알고 있지만, 아직 수주잔고·납기·마진·고객계약·interconnect queue까지 충분히 연결하지 못한 후보가 많다.

다섯 번째 병목은 optical/networking/interconnect와 geography/export-control fragmentation이다. Agent/inference workload가 늘면 cluster 내부 east-west traffic, retrieval/cache traffic, disaggregated memory, model routing, multi-data-center training/inference traffic이 늘어난다. Copper SerDes의 power/latency/distance 한계가 커질수록 co-packaged optics, optical I/O chiplet, photonic fabric, 800G/1.6T optical module, switching silicon이 중요해진다. 동시에 export-control, sovereign AI, regional energy advantage는 supply chain과 data-center geography를 분절시킬 수 있다. 깨는 기술은 optical I/O, CPO, photonic interposer, high-radix switching, optical DSP, regional supply-chain compliance다. Timing window는 12~30개월이다. 이 병목은 hype가 빠르게 붙기 쉬우므로 design win, production capacity, actual shipment, export license, customer acceptance가 필요하다.

4. 병목별 수혜 산업과 회사 후보

Stateful agent runtime·eval/security gate에서는 상장사보다 open-source·private infrastructure가 더 직접적인 경우가 많다. vLLM, SGLang, Ray/Anyscale, Modal, Baseten, Fireworks, Together AI 같은 serving/runtime 계층은 Tier S/A 관찰 후보가 될 수 있다. LangChain/LangSmith, Arize/Phoenix, Weights & Biases, Humanloop, Giskard, Prompt Security, Vett 같은 eval/observability/security 계층도 병목을 직접 건드린다. Public proxy로는 Microsoft/GitHub, Amazon, Alphabet, Oracle, Cloudflare, Datadog, Elastic, ServiceNow, Atlassian, Palo Alto Networks, CrowdStrike를 볼 수 있지만, 이들은 대부분 Tier B/A 후보다. Agent 권한·trace·eval·security가 제품 gate로 실제 채택됐다는 근거가 없으면 narrative beta로 낮춰야 한다.

Long-context/KV/RAG 비용과 memory bandwidth에서는 NVIDIA가 GPU·networking·software stack을 묶기 때문에 Tier S/A 경계에 있지만, HBM 병목을 “소비”하는 쪽이기도 하다. AMD는 accelerator challenger, Broadcom과 Marvell은 custom silicon/network silicon, hyperscaler는 자체 silicon과 serving economics 때문에 Tier A/B 관찰 후보가 된다. CoreWeave와 Nebius 같은 AI cloud/neocloud는 capacity provider이지만 capex financing, utilization, customer concentration, power/cooling 병목을 동시에 가진다. 이 영역의 핵심 검증은 “GPU를 더 샀는가”가 아니라 inference margin, utilization, capacity booking, customer retention, serving efficiency, debt-funded capex 부담이다.

HBM bandwidth와 advanced packaging/inspection에서는 후보를 더 엄격히 나눠야 한다. BESI, ASMPT, 한미반도체는 bonding/stacking 장비 축에서 Tier S/A 관찰 후보가 될 수 있다. SK하이닉스, 삼성전자, Micron은 HBM 공급과 qualification의 핵심이지만, 병목을 깨는 장비/공정 주체라기보다는 capacity와 customer allocation 축이다. TSMC는 CoWoS/advanced packaging capacity 때문에 Tier S/A 경계다. KLA, Onto Innovation, Camtek, 인텍플러스는 inspection/metrology 병목을 직접 줄이는 Tier S/A 후보로 볼 수 있다. ISC, 리노공업, HPSP, 원익IPS는 test/socket/semicap derivative enabler로 관찰하되, 고객·제품 mix·수율·수주·margin·revision이 붙기 전까지 Tier B/A를 넘기 어렵다. Samsung Electro-Mechanics, Ibiden, Unimicron, Intel glass substrate는 advanced packaging capacity wall의 S-watch 후보지만 source pack이 아직 부족하다.

Rack power·cooling·grid에서는 Vicor와 Monolithic Power가 vertical/rack power module 쪽 S-watch 후보이고, Vertiv는 data-center power/cooling integration에서 Tier S/A 경계 후보다. Eaton, Schneider Electric, Quanta Services, GE Vernova, Constellation Energy는 indispensable infrastructure 또는 derivative enabler로 본다. 한국 proxy로는 HD현대일렉트릭, LS ELECTRIC, 효성중공업, 일진전기가 transformer, switchgear, heavy electrical equipment, cable/grid equipment 쪽 Tier A 후보가 될 수 있다. 단, 전력 인프라 narrative는 이미 시장에 많이 알려져 있으므로 수주잔고, book-to-bill, 납기, 지역/customer mix, 판가, margin, capacity 증설이 없으면 Tier를 올리지 않는다. SMR/원전 계열은 narrative가 강하지만 규제·건설·계약 timing이 길어 보수적으로 Tier B/C에서 시작한다.

Optical/networking/interconnect에서는 private 후보가 더 직접적이다. Lightmatter, Ayar Labs, Celestial AI는 optical I/O·photonic fabric 병목을 직접 깨려는 Tier S private watch다. Public proxy로는 Broadcom, Marvell, Coherent, Lumentum, Ciena, Arista, Cisco, Corning을 본다. Broadcom과 Marvell은 custom silicon·switching·optical DSP 연결 때문에 Tier A에 가깝고, Coherent/Lumentum/Ciena는 optical component/networking infrastructure로 Tier A/B 후보다. Arista/Cisco는 network buildout 수혜 가능성이 있지만 병목 자체를 깨는지 확인해야 하므로 Tier B/A로 둔다. 한국 proxy인 빛과전자, LG이노텍, 오이솔루션은 AI data-center용 SKU, 800G/1.6T, 고객 qualification, 실제 수주가 확인되기 전까지 Tier B/C에서 출발한다.

Robotics/on-device/physical AI는 이번 주 반복 신호가 강하지만, base case의 핵심 병목 breaker라기보다 upside surface다. NVIDIA Isaac/Jetson, Qualcomm, Arm, Apple, Teradyne/Universal Robots, Fanuc, Rockwell Automation, Tesla, Hyundai/Boston Dynamics, Doosan Robotics, Rainbow Robotics, Mobilint/Nota AI류는 관찰 후보가 될 수 있다. 그러나 robot headline, 파트너십, 일회성 주가 움직임만으로는 부족하다. Sensor/actuator/safety stack, edge NPU, local memory, simulation-to-real, field deployment, 반복 주문, warranty/maintenance economics가 붙어야 Tier가 오른다.

5. 공개주 / 비상장 / 한국 proxy

Public US/EU 후보는 네 묶음으로 나누어 관찰한다. 첫째, compute/inference/capacity layer는 NVIDIA, AMD, Broadcom, Marvell, TSMC, Microsoft, Amazon, Alphabet, Oracle, CoreWeave, Nebius다. 이들은 AI workload를 capacity로 바꾸는 계층이지만, 일부는 capex financing과 utilization risk를 동시에 갖는다. 둘째, physical infrastructure layer는 Vertiv, Eaton, Schneider Electric, Quanta Services, GE Vernova, Constellation Energy, Arista, Ciena, Coherent, Lumentum이다. 셋째, software/security/data layer는 Datadog, Elastic, Cloudflare, ServiceNow, Atlassian, Palo Alto Networks, CrowdStrike, Snowflake, MongoDB다. 넷째, robotics/on-device layer는 Qualcomm, Arm, Apple, Tesla, Teradyne, Rockwell Automation, Intuitive Surgical 등이다. 이 분류는 투자 행동 후보가 아니라 어떤 병목에 노출되는지 보기 위한 관찰 지도다.

Private/IPO watch는 더 직접적인 bottleneck breaker가 많지만 접근성과 검증이 어렵다. Lightmatter, Ayar Labs, Celestial AI는 optical/photonic interconnect 후보이고, Lambda, Together AI, Fireworks, Modal, Baseten, Anyscale은 inference/runtime capacity 후보이며, LangChain/LangSmith, Arize, Weights & Biases, Humanloop, Giskard, Prompt Security는 eval/observability/security gate 후보로 본다. Figure AI, 1X, Agility Robotics 같은 robotics 후보는 현장 deployment와 반복 주문이 확인되기 전까지 public proxy로 바로 번역하지 않는다.

한국 proxy는 더 엄격히 본다. SK하이닉스는 HBM leadership 때문에 core 관찰 후보지만 customer concentration과 cycle risk를 같이 봐야 한다. 삼성전자는 generic AI/HBM beneficiary가 아니라 DRAM/DDR5 ASP, HBM shipment/yield/share catch-up, NAND 회복, foundry/System LSI drag, MX/mobile, 자본환원, EPS revision을 분리해야 한다. 한미반도체와 인텍플러스는 HBM/advanced packaging 장비·검사 병목에 직접 닿아 있지만 고객·수주·경쟁·throughput을 확인해야 한다. ISC와 리노공업은 AI chip test socket/pin, HPSP와 원익IPS는 선단공정/장비 cycle, 파두는 AI data-center storage/cache 병목으로 보되 각각 source pack과 revision gate가 필요하다. HD현대일렉트릭, LS ELECTRIC, 효성중공업, 일진전기는 power/grid 병목 proxy다. 삼성SDS, NAVER, Kakao는 enterprise/sovereign/platform AI proxy지만 agent runtime 병목을 직접 깨는지 확인해야 한다. 두산로보틱스, 레인보우로보틱스, 루닛은 physical/healthcare AI adoption surface로 보되, 반복 주문·임상/규제·매출 전환 전에는 Tier B/C에서 시작한다.

이번 주 Tier 감각은 다음과 같다. Tier S — Bottleneck Breaker는 병목 자체를 깨는 기술·공정·아키텍처 또는 측정 능력이 있어야 한다. Tier A — Indispensable Infrastructure는 병목 해결에 필수지만 직접 breaker는 아닐 수 있다. Tier B — Derivative Enabler는 수혜 가능성은 있으나 핵심 병목 레버가 약하다. Tier C — Narrative Beta는 테마 노출은 있으나 기술력·수주·qualification·revision evidence가 부족한 상태다. 현재 많은 회사 리포트가 provisional이고 source pack·sell-side revision history가 미완성인 만큼, 개별 결론은 기본적으로 판단 보류다.

6. 다음 주 확인할 것

첫째, agent runtime/eval/security가 제품 gate로 들어가는지 본다. Release note에서 sandbox, permission, trace/replay, eval harness, RAG provenance, MCP capability control, security boundary가 반복되는지 확인한다. Benchmark 점수보다 paid workflow, production reference, failure-rate reduction, security incident 부재가 중요하다.

둘째, HBM/advanced packaging의 심화 또는 완화를 본다. HBM3E/HBM4 qualification, customer allocation, TSV/yield, CoWoS capacity, hybrid bonding throughput, package inspection/metrology, test socket demand, substrate lead time, ASP/bit shipment을 확인한다. 단순 HBM 수혜 headline은 충분하지 않다.

셋째, hyperscaler와 AI cloud의 capex ROI 언어를 본다. Capex 총액보다 utilization, AI revenue contribution, inference margin, capacity booking, RPO/backlog conversion, power delay, customer concentration, debt-funded capex 부담이 중요하다. Microsoft, Meta, Amazon, Alphabet, Oracle, CoreWeave, Nebius 관련 뉴스는 “얼마나 쓰나”보다 “그 지출이 capacity와 revenue로 어떻게 돌아오나”로 읽는다.

넷째, power/cooling/grid의 backlog와 납기를 본다. Transformer, switchgear, liquid cooling, 48V/rack power, grid interconnect, PPA/nuclear/gas contract, permitting이 수주·납기·마진으로 연결되는지 확인한다. 전력 narrative는 이미 알려졌으므로 증거 없이 Tier를 올리면 과열 가능성이 높다.

다섯째, optical/networking/interconnect의 design win과 shipment를 본다. 800G/1.6T optical module, CPO, optical I/O chiplet, switching silicon, photonic fabric이 실제 고객 acceptance와 production capacity로 이어지는지 확인한다. Optical headline만 반복되면 narrative beta로 낮춘다.

여섯째, robotics/on-device의 반복 deployment를 본다. Humanoid, household robot, industrial robot, AI PC, edge device headline은 많아졌지만 field deployment, 반복 주문, safety certification, edge AI attach rate, sensor/actuator supply chain, maintenance economics가 붙어야 한다.

일곱째, geopolitics/export-control과 regional AI infra geography를 본다. 이번 주 직접 export-control 신호는 약했지만, 중국 robotics, sovereign AI, data-center energy geography는 계속 남아 있다. Export license, restricted chip shipment, local accelerator adoption, energy permitting, government-backed AI infra가 같은 병목을 강화하는지 확인한다.

여덟째, source quality와 revision data gap을 본다. Google News/RSS headline은 discovery에는 유용하지만 source pack이 아니다. 개별 회사 판단은 IR·filing·산업 자료·증권사/컨센서스 revision·수주/백로그 원문이 붙기 전까지 보류한다.

7. 판단의 약점

첫 번째 약점은 research signal과 adoption evidence 사이의 거리다. Agent/memory/eval 논문이 많다고 해서 enterprise paid deployment가 이미 확인된 것은 아니다. 논문은 병목 위치를 알려주지만, 돈이 움직이는 시점은 제품 gate, 고객 계약, 보안 승인, workflow retention이 붙을 때다.

두 번째 약점은 market headline의 품질이다. 이번 주 Market Brief에는 Reuters, CNBC, Bloomberg, WSJ, Nikkei, NVIDIA Newsroom 같은 상대적으로 좋은 근거도 있었지만, Dailyhunt, 24/7 Wall St., 일부 보조/저신뢰 출처도 섞여 있다. 따라서 한 주의 headline 반복만으로 수주·마진·revision을 판단하면 안 된다.

세 번째 약점은 company source pack의 미완성이다. 로컬 회사 리포트 상당수는 provisional 상태이며 verified sell-side revision history, original report/estimate table, numeric reconciliation, IR/filing source pack이 부족하다. 이 보고서의 Tier는 투자 결론이 아니라 다음 검증 우선순위다.

네 번째 약점은 private/open-source layer가 핵심인 영역이 많다는 점이다. Agent runtime, eval/security, optical I/O, inference platform은 실제 bottleneck breaker가 비상장 또는 open-source일 가능성이 크다. Public proxy는 간접 수혜에 그칠 수 있으므로, 상장사의 기술적 병목 해결력을 따로 확인해야 한다.

다섯 번째 약점은 가격 데이터 해석이다. 이번 보고서는 단기 가격 움직임을 결론 근거로 쓰지 않는다. 가격 데이터가 없거나 출처가 불완전한 경우 확인 필요로 두고, 병목과 evidence를 먼저 본다. EPS/consensus revision 이력도 아직 검증 소스가 부족하므로 결론을 강하게 내리지 않는다.

여섯 번째 약점은 export-control 신호의 약함이다. 이번 주 local report에서는 지정학/export-control이 market context로 일부 잡혔지만, 실제 정책 공지·license·shipment·우회 단속 근거는 강하지 않았다. 따라서 export-control은 base의 중심이 아니라 risk modifier로 둔다.

8. 8~12주 플래닝 전략

이번 8~12주 운영 순서는 시나리오 유지/폐기 → 병목 강화/약화 → Tier 조정 → 다음 검증 질문이다. 회사는 마지막에만 올린다.

  • Root hypothesis: Agent와 Physical AI 연구가 long-horizon workflow, memory, eval/security, inference/KV 비용을 키운다. 이 비용은 cloud inference와 AI data center capex로 전파되고, 다시 HBM/advanced packaging/inspection, rack power/cooling/grid, optical/networking 병목으로 내려간다. 시장은 처음에는 broad AI/robotics/HBM/power narrative로 반응하지만, 시간이 지나면 병목을 실제로 깨는 기술·인프라와 narrative beta를 분리한다.
  • Confirm trigger: agent paid deployment, production-grade eval/security adoption, sandbox/permission/replay 기능 release, long-context serving cost 개선, cloud inference utilization/margin 개선, HBM3E/HBM4 qualification, CoWoS/advanced packaging throughput, hybrid bonding/metrology order, power equipment backlog·납기·마진, optical/CPO design win, robotics 반복 주문이 2~3개 이상 같은 방향으로 확인되면 Base를 강화한다.
  • Invalidation trigger: hyperscaler가 capex ROI 우려를 공식화하고 AI revenue contribution이 약해지거나, agent adoption이 security/reliability 사고로 지연되거나, HBM/CoWoS/optical/power 병목이 수요를 막아 capacity가 지연되거나, robotics/on-device가 demo에 머물고 반복 주문이 없으면 Base를 약화한다. 이 경우 AI capex 피로와 병목 해결 지연 Downside로 전환한다.
  • Tier 상향 조건: Tier B/C 후보는 고객 채택, 수주/백로그, qualification, yield/throughput, production reference, security boundary, 반복 매출, verified EPS/consensus revision evidence가 붙을 때만 Tier S/A로 올린다. Robotics 후보는 field deployment와 반복 주문, software/eval 후보는 enterprise workflow gate 채택, HBM/packaging 후보는 고객 qualification과 수율·throughput, power 후보는 backlog와 납기·마진이 필요하다.
  • Tier 하향 조건: 테마 단어, 단기 가격 움직임, 파트너 이름, 발표 자료만 있고 고객·수율·수주·revision·반복 매출이 따라오지 않으면 Tier를 낮춘다. 특히 AI security, robotics, data center, HBM supply chain, nuclear for AI, optical AI data center라는 이름만 있고 검증 가능한 운영 지표가 없으면 narrative beta로 되돌린다.
  • 다음 4주 최우선 관찰 지표: hyperscaler utilization/inference margin, AI cloud capacity booking/RPO, agent paid deployment와 security incident 부재, HBM3E/HBM4 qualification, CoWoS/advanced packaging yield, hybrid bonding/metrology throughput, transformer/switchgear/liquid cooling backlog, 48V/rack power adoption, optical/CPO design win, export-license 실제 shipment, robotics 반복 주문을 우선 관찰한다.

첫 4주는 signal alignment를 본다. AI research가 agent memory/eval/runtime으로 계속 쌓이는데 market이 power/HBM/packaging/capex로 같이 움직이면 Base를 유지한다. Research signal만 강하고 market이 따라오지 않으면 timing lag로 기록하고, market price만 움직이고 source evidence가 없으면 narrative beta로 낮춘다.

5~8주차에는 병목별로 가장 좁은 구간을 하나씩 고른다. 현재 후보는 stateful runtime/eval security, long-context/KV memory, HBM/advanced packaging/inspection, rack power/cooling/grid, optical/networking이다. 이 중 실제 고객 채택·수주·qualification evidence가 가장 빨리 붙는 하나를 별도 deep-dive로 승격한다.

9~12주차에는 alternative scenario를 강제로 검토한다. Base가 맞다면 software adoption과 physical infra order가 동시에 일부 확인되어야 한다. 그렇지 않고 capex ROI 의심, agent 신뢰성 사고, packaging/optical 지연, 전력 수주 둔화가 누적되면 Downside로 전환한다. 반대로 agent production adoption과 물리 병목 주문이 동시에 강해지면 Upside로 전환하되, 그때도 회사 리스트가 아니라 병목 breaker evidence부터 다시 쓴다.
