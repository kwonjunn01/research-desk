Weekly Scenario Planning — 2026-08-30

투자 추천이 아니다. 공개 정보와 Research Desk 수집 자료를 바탕으로, 이번 주 AI research signal이 어떤 시장·산업 병목과 검증 질문으로 이어지는지 정리한 관찰 보고서다. 개별 거래 행동, 목표가, 확정 수익률을 제시하지 않는다.
Judgment state: source incomplete / public provisional / judgment hold. Price, EPS, consensus revision tape가 연결되지 않은 edge는 “시장 미반영”이 아니라 검증할 공백으로만 취급한다.

0. 이번 주 한줄 결론

이번 주 base case는 “agent가 실제 업무를 더 오래 수행할수록 병목은 모델 크기보다 verifiable trajectory, evaluation harness, memory/RAG provenance, KV-cache·inference economics로 이동하고, 이 소프트웨어 병목이 HBM/advanced packaging/test, 전력·냉각·그리드, optical/networking·AI storage 같은 물리 병목으로 전파되지만, 시장은 broad AI theme가 아니라 hard evidence가 붙은 병목 layer만 선별해 재평가하는 경로”다.

지난주와 달라진 점은 방향 자체보다 병목의 표현이 더 좁아졌다는 것이다. AI research 쪽에서는 Agentic Game Development, FrontierChallenge, What Makes Good Agentic Data?, TaoLive Harness, WeMM-Embedding, TTPO가 “agent가 남긴 실행 로그·memory·harness·보상 신호를 어떻게 검증 가능한 학습/운영 재료로 바꿀 것인가”를 반복했다. 시장 쪽에서는 HBM Memory, Robotics, AI Semiconductor, Cloud Hyperscaler, Power Infrastructure가 계속 뜨지만, Reuters의 SK Hynix memory shortage-through-2030 보도와 capex angst 완화/부담 기사, Reuters의 중국 humanoid robot factory-use gap 보도가 동시에 잡혔다. 결론은 “AI 수혜주를 찾자”가 아니라 어떤 병목은 실제로 타이트해지고, 어떤 병목은 아직 데모·헤드라인 단계인지 분리하자다.

1. 이번 주 가장 그럴듯한 시나리오

이번 주의 AI 신호는 2026-08-24~08-30 내내 비슷한 모양이었다. Agentic AI와 AI Research가 최상단을 차지했고, Inference Stack, Post-training, Agent Evaluation, On-device LLM, RAG / Memory가 매일 따라붙었다. 8월 24일의 Graph Engineering in the Era of LLM Agents는 agent를 개별 지능이 아니라 시스템 지능으로 다루는 방향을, 8월 25일의 Apodex 1.1은 complex work를 수행하는 agentic intelligence를, 8월 26일의 WeMM-Embedding은 retrieval set 품질과 multimodal memory를, 8월 27~28일의 FrontierChallenge는 scientific workflow completion 평가를, 8월 29~30일의 Agentic Game Development as a Verifiable Trajectory Data Engine는 agent 실행 로그를 long-context/world-model 학습 재료로 전환하는 방향을 보여줬다.

이 흐름의 원인은 단순히 “agent 논문이 많다”가 아니다. Agent가 실제 업무를 맡으려면 답변 하나를 잘하는 것보다 실행 상태를 보존하고, 실패를 복구하고, tool log와 memory를 재현 가능하게 남기며, 권한·보안 boundary를 통과하고, 그 모든 과정을 평가할 수 있어야 한다. 그래서 이번 주 AI research의 전파 경로는 다음처럼 읽는다.

Agentic AI / Tool-use / Post-training / RAG-Memory / On-device-Robotics
→ verifiable trajectory + harness + memory provenance + permissioned runtime
→ longer context, KV-cache, inference scheduling, retrieval cache, tool-log storage
→ cloud workload, HBM/DRAM, advanced packaging/test, power/cooling/grid, optical/networking, AI-storage
→ usage, order, backlog, utilization, margin, EPS/consensus revision 검증

시장 쪽은 같은 방향을 바로 확정하지 않는다. 2026-08-24~08-28 Market Brief와 market source에서 HBM Memory는 매일 상위 signal score를 유지했고, Robotics, AI Semiconductor, Cloud Hyperscaler, Power Infrastructure, On-device AI도 반복됐다. 고품질 근거로는 Reuters의 “SK Hynix to start AI chip output in Indiana in 2029, sees memory shortage through 2030”, Reuters의 “Big investors hunt for tomorrow's AI winners as capex angst fades”, Bloomberg/WSJ의 Nvidia 관련 정책·cloud financing/거래구조 기사, Reuters의 “China can build kung fu-fighting robots. But it can’t get them to do factory work”가 잡혔다. 즉 시장은 AI capex가 끝났다고 보지는 않지만, capex가 실제 capacity, utilization, backlog, memory shortage, factory deployment로 이어지는지를 더 날카롭게 요구하는 상태다.

이번 주 시나리오 매트릭스는 세 갈래다.

  • Base — 선택적 production-agent 확산 + hard bottleneck 선별 재평가. Agent 연구는 더 강해지지만 enterprise adoption은 evaluation, trace/replay, memory governance, security, inference cost를 통과한 workflow만 확장된다. 시장은 capex 총액보다 HBM supply/qualification, CoWoS·advanced packaging capacity, power/cooling/grid backlog, optical/networking deployment, AI storage/log lifecycle, cloud utilization과 margin을 요구한다. 이 시나리오를 중심으로 채택한다.
  • Upside — agent usage와 물리 병목 주문이 동시에 확인된다. Verifiable trajectory, harness, RAG provenance, tool-call volume, workflow retention이 실제 제품 release note와 enterprise 계약으로 확인되고, 동시에 HBM3E/HBM4, advanced packaging, liquid cooling, transformer/switchgear, 800G/1.6T optics, custom silicon order가 반복되면 시장은 AI capex를 부담이 아니라 capacity bottleneck 해결 cycle로 다시 본다.
  • Downside — research signal은 강하지만 production gate와 capex ROI가 막힌다. Agent가 benchmark·demo에 머물고 memory/RAG failure, 보안·권한 사고, workflow retention 부재가 드러나거나, hyperscaler가 depreciation/FCF/margin 부담을 공식화하고 usage·revenue conversion이 약하면 AI capex fatigue가 우세해진다. 이 경우 HBM, robotics, on-device, SMR, CPO, AI storage 헤드라인은 narrative beta로 낮춘다.

가장 그럴듯한 중심축은 Base다. 이번 주 신호는 “AI 수요 폭발”이나 “AI bubble 붕괴” 중 하나로 정렬되지 않았다. 오히려 agent 실사용 병목은 더 구체화됐고, 시장은 같은 AI theme 안에서도 실제 병목 해결력과 검증 공백을 더 엄격히 가르는 방향으로 움직였다.

2. 왜 이 시나리오가 base case인가

첫째, AI research의 상단이 “능력 과시”에서 “검증 가능한 실행 데이터와 운영 gate”로 이동했다. 8월 30일의 Agentic Game Development as a Verifiable Trajectory Data Engine는 agent 실행 로그를 long-context/world-model 학습 재료로 바꾸려는 시도다. 8월 28일의 FrontierChallenge는 scientific workflow completion을 평가하고, 8월 30일의 What Makes Good Agentic Data?는 환경·task·interaction·success signal의 일관성을 묻는다. 8월 26일의 WeMM-Embedding은 retrieval set 품질이 agent 답변의 상한이 된다는 쪽을 건드린다. 이것들은 모두 “더 큰 모델”보다 실제 업무에서 남는 trajectory, memory, 평가, 보안, 운영 로그를 어떻게 다루는가를 묻는다.

둘째, cross-ontology edge가 5일 연속 같은 구조로 반복됐다. inference_cost_pressure_links_to_capex_and_power, workload_shift_creates_edge_device_demand, retrieval_trust_risk_controls_enterprise_adoption, agent_workflows_drive_cloud_and_enterprise_adoption, model_capability_gains_raise_or_reprice_compute_demand가 2026-08-24~08-28 모두 등장했다. 특히 8월 28일에는 model_capability_gains_raise_or_reprice_compute_demand가 edge_strength 4/5, recognition_gap 4/5, action_type new_company_intake로 올라왔다. 하지만 같은 파일은 adoption evidence를 여전히 “미확인”으로 남겼다. 이것이 Base의 핵심이다. 관심도는 강하지만, 아직 usage, spend, order, backlog, EPS/consensus revision이 한 줄로 연결되지 않았다.

셋째, 시장 narrative는 HBM과 capex를 계속 본다. 8월 24~28일 market source에서 HBM Memory는 대체로 최상단 signal score를 유지했고, 8월 28일 Market Brief의 top themes도 HBM Memory 33, Robotics 32, AI Semiconductor 30, Cloud Hyperscaler 27, On-device AI 25, Power Infrastructure 23이었다. Reuters의 SK Hynix memory shortage-through-2030 보도는 HBM/메모리 병목이 단순한 하루짜리 headline이 아니라 2029~2030 capacity calendar와 연결될 수 있음을 보여준다. 그러나 같은 보고서의 Bottleneck Radar는 Advanced Packaging/CoWoS, Power/Grid/Cooling, Hyperscaler Capex 회수를 모두 혼재로 둔다. 즉 병목은 보이지만, 해결 속도와 수익 전환은 아직 검증 공백이다.

넷째, robotics/on-device 신호는 강하지만 base의 중심으로 올리기에는 아직 이르다. 8월 28일 Reuters는 중국이 kung fu-fighting robots를 만들 수 있지만 factory work에는 아직 못 미친다는 점을 짚었다. 이는 robotics signal을 무시하라는 뜻이 아니라, 이번 주에는 demo capability와 factory deployment 사이의 gap이 더 중요한 신호라는 뜻이다. On-device AI도 Perplexity on-device offering, AI glasses, smartphone AI ASIC 같은 headline이 있지만, 실제 출하, attach-rate, paid runtime adoption, BOM 증가, edge semiconductor order가 붙기 전까지는 core thesis가 아니라 관찰 후보에 가깝다.

다섯째, geopolitics/export-control은 독립 시나리오라기보다 모든 병목에 붙는 risk multiplier다. Nvidia의 DC 영향력 확대, export risk가 붙은 Vera Rubin cluster 보도, sovereign AI/data center geography는 GPU/HBM/advanced packaging의 공급 위치와 고객 접근성을 바꿀 수 있다. 다만 정책 headline만으로 회사 Tier를 올리거나 낮추지 않는다. 실제 license, enforcement, China demand substitution, regional capex relocation, supplier qualification이 확인되어야 한다.

여섯째, 최신 완전 시장 리포트는 2026-08-28까지이고, 2026-08-30 market-sources exact 파일은 price-only 성격이 강하다. 따라서 이번 보고서는 8월 30일 AI research를 반영하되, market narrative는 8월 24~28일의 완전 news+price 소스를 중심으로 읽는다. 이 한계 때문에 결론은 더 보수적으로 둔다. Base는 확정 전망이 아니라, 다음 8~12주 동안 유지/폐기할 working hypothesis다.

3. 이 시나리오가 만드는 병목 3~5개

3.1 Agent runtime·evaluation·security gate

첫 번째 병목은 agent runtime, evaluation, security gate다. Agent가 scientific workflow, terminal work, browser/computer use, personal assistant, enterprise workflow로 들어가면 “모델이 정답을 맞히는가”보다 “실제 환경에서 어떤 상태를 바꿨고, 실패했을 때 어디서 멈췄으며, 다시 실행하면 같은 결과가 나오는가”가 더 중요해진다. 8월 27~30일의 FrontierChallenge, verifiable trajectory data, agentic data generation, TaoLive harness 신호가 모두 이 방향이다.

이 병목을 깨는 기술은 model parameter scaling만으로는 부족하다. Persistent workspace, sandbox, permissioned tool-use, trace/replay, partial-success scoring, long-running task monitoring, eval harness, red-team, workflow rollback, security policy enforcement가 필요하다. Timing window는 0~18개월이다. 연구와 developer tooling은 빠르게 움직일 수 있지만, enterprise adoption은 보안·조달·권한 boundary 때문에 늦게 반영된다. 시장은 아직 이 레이어를 “AI app” 또는 “cloud capex”로 뭉뚱그려 보기 쉽기 때문에, agent ops/runtime을 독립 병목으로 추적해야 한다.

3.2 Memory/RAG provenance와 KV-cache·inference economics

두 번째 병목은 memory/RAG provenance와 KV-cache·inference economics다. Agent가 길게 일할수록 retrieval set, memory entry, tool log, browser trace, intermediate artifact가 늘어난다. 이때 답변 품질은 모델 자체보다 retrieval quality, memory precision, cache invalidation, context window management, KV-cache memory footprint, prefill latency, scheduler efficiency에 묶인다. 8월 26일 WeMM-Embedding, 8월 28일 RetrievalRouter, 8월 30일 CaSKG와 CritICL류의 신호는 이 병목을 가리킨다.

이 병목은 양방향이다. KV/cache 최적화와 inference-time 방법이 단위 비용을 낮추면 하나의 task는 싸질 수 있다. 그러나 비용이 내려가면 더 긴 agent session, 더 많은 tool call, 더 큰 retrieval cache, 더 많은 memory/log retention이 가능해져 총 workload는 오히려 커질 수 있다. Breaking technology는 KV-cache compression/offload, prefix/prompt cache, retrieval routing, memory hygiene, access-control-aware RAG, citation/provenance, model routing, speculative decoding, batch/scheduler optimization이다. Timing window는 3~24개월이다. 핵심 검증 질문은 serving cost per task와 session length, tool-call volume, cloud AI gross margin, HBM/DRAM content, eSSD/nearline storage demand가 같은 방향으로 움직이는가다.

3.3 HBM·advanced packaging·test/inspection qualification wall

세 번째 병목은 HBM, advanced packaging, test/inspection qualification wall이다. Reuters가 잡은 SK Hynix의 “memory shortage through 2030”와 Indiana production base timing은 메모리 병목이 단순 가격 headline이 아니라 capacity calendar와 연결되어 있음을 보여준다. 그러나 시장이 이미 HBM이라는 단어에 익숙해졌기 때문에, 이번 주에는 더 좁게 봐야 한다. HBM3E/HBM4 qualification, stack yield, TSV, TC bonding, hybrid bonding, CoWoS/interposer capacity, package warpage, inspection/metrology, test socket/probe throughput이 실제 gate다.

이 병목을 깨는 기술은 더 많은 memory fab만이 아니다. HBM stack 설계와 수율, packaging throughput, interposer/substrate capacity, 검사·계측 precision, socket/probe reliability, OSAT/foundry scheduling이 같이 움직여야 한다. Timing window는 6~30개월이다. Indiana production base처럼 2029년 이후로 보이는 capacity는 1~2년 시장 narrative에는 “완화 예정”보다 “현재 shortage가 길다”는 신호로 작동할 수 있다. 검증 질문은 HBM shipment, customer qualification, yield, bit shipment, ASP, CoWoS capacity, bonder backlog, inspection order, test socket demand, OP/EPS revision이 같은 방향인지다.

3.4 Data-center power·cooling·grid와 capex ROI gate

네 번째 병목은 data-center physical build-out이다. AI workload가 늘어도 data center가 실제로 세워지려면 grid interconnect, transformer lead time, switchgear, UPS/PDU/busway, liquid cooling, rack density, PPA, permitting, site selection을 통과해야 한다. 8월 28일 Market Brief는 Power Infrastructure를 상위 theme로 잡았고, nuclear/power/grid 관련 보조 근거도 계속 들어왔다. 동시에 Hyperscaler Capex 회수는 혼재로 남았다. 전력·냉각 병목은 capex가 실제 capacity로 전환되는 속도를 좌우한다.

Breaking technology와 운영 레이어는 48V/rack power, high-density power module, liquid cooling/CDU/cold plate, transformer/switchgear capacity, grid EPC, onsite/off-grid power, nuclear/gas/PPA contracting이다. Timing window는 12~36개월로 가장 inertia가 길다. 시장은 전력 headline을 좋아하지만, 실제로 중요한 것은 order/backlog/book-to-bill, lead time, data-center customer mix, margin conversion, permitting delay, PPA/offtake 계약이다. 검증 질문은 AI capex가 cloud utilization·margin으로 회수되는 동시에 power/cooling/grid backlog가 반복 확인되는가다.

3.5 Optical/networking·AI storage와 robotics/on-device deployment gap

다섯 번째 병목은 cloud 내부의 scale-out I/O와 cloud 바깥의 edge deployment gap이 동시에 커지는 구간이다. AI cluster가 커질수록 GPU 간 통신은 copper SerDes power, latency, bandwidth density, switch fabric, optical link, 800G/1.6T optics, CPO/photonic I/O에 묶인다. Agent workflow가 길어질수록 checkpoint, synthetic data, inference log, tool-use trace, RAG corpus, audit archive가 늘어 AI storage lifecycle도 커진다. 이번 주 optical signal은 HBM·robotics보다 약했지만, 1~2년 시나리오에서는 구조적 병목 후보로 유지한다.

동시에 robotics/on-device는 “cloud를 대체한다”보다 “새로운 edge workload surface를 만든다”에 가깝다. 그러나 Reuters의 factory-use gap 보도처럼, humanoid/robot demo가 실제 공장 작업, 안전 인증, uptime, maintenance, unit economics로 이어지지 않으면 핵심 병목이 아니라 hype로 남는다. Breaking technology는 AI Ethernet/switch silicon, optical DSP, photonic I/O, eSSD/nearline storage, edge runtime, sensor/actuator control, real-world eval, safety stack이다. Timing window는 optical/networking 6~24개월, robotics/on-device 12~36개월이다. 검증 질문은 800G/1.6T shipment, custom ASIC/networking revenue, eSSD design-win, nearline exabytes, robot deployment order, AI PC/mobile attach-rate, factory uptime evidence가 붙는가다.

4. 병목별 수혜 산업과 회사 후보

이 섹션은 추천 리스트가 아니다. 회사는 병목을 실제로 깨거나, 측정하거나, 운영하는 후보로만 기록한다. Registry와 company report의 다수 항목은 아직 provisional / judgment hold 상태이며, IR·filing·industry source pack·verified sell-side revision history가 미완성인 곳은 강한 결론을 내리지 않는다.

Agent runtime·evaluation·security gate에서는 public company보다 private/open-source 레이어가 더 직접적인 bottleneck breaker일 수 있다. LangChain/LangSmith, LlamaIndex, Braintrust, Arize/Phoenix, Weights & Biases, Humanloop, Giskard, Protect AI, Lakera, Prompt Security류는 eval, observability, red-team, data governance의 직접 후보지만 source-pack이 필요하다. Public proxy로는 Microsoft/GitHub/Azure, Amazon/AWS, Alphabet/Google Cloud, Cloudflare, Datadog, CrowdStrike, Palo Alto Networks, ServiceNow, MongoDB, Snowflake가 있다. 이 중 Microsoft, CrowdStrike, Palo Alto Networks는 Tier A 후보로 볼 수 있지만, agent workflow paid adoption, ARR/RPO/retention, 보안 gate 통과, margin impact가 확인되기 전까지는 judgment hold다. Datadog, Cloudflare, MongoDB, Snowflake는 Tier B~A 후보이며, 단순 “AI 기능 추가” 마케팅만 있으면 Tier C로 낮춘다.

Memory/RAG provenance와 KV-cache·inference economics에서는 NVIDIA가 GPU, CUDA/software, networking, inference stack을 함께 쥐고 있어 Tier S/A 경계에 있다. 다만 NVIDIA는 병목을 푸는 회사이면서 동시에 병목을 소비하는 demand node이므로, Blackwell/Data Center 매출, gross margin, HBM/CoWoS allocation, inference utilization, customer concentration을 분리해야 한다. AMD는 second-source accelerator와 enterprise inference option으로 Tier A/B 후보다. Broadcom과 Marvell은 custom ASIC, switching silicon, optical DSP, electro-optics 경로에서 Tier A 후보다. vLLM, SGLang, Ray/Anyscale, Together AI, Fireworks AI, Groq, Cerebras는 inference efficiency 후보지만 상장 proxy로 바로 번역하지 않는다. HBM/DRAM 쪽에서는 SK Hynix가 Tier S, Micron과 Samsung Electronics가 Tier A~S 후보이나, Samsung Electronics는 HBM catch-up, legacy DRAM/NAND, foundry/System LSI drag, MX/mobile, EPS revision을 분리해야 한다.

HBM·advanced packaging·test/inspection에서는 SK Hynix, Samsung Electronics, Micron, TSMC가 핵심 public 후보로 남는다. TSMC는 CoWoS/advanced packaging capacity 때문에 Tier S/A 경계다. Hanmi Semiconductor는 HBM TC bonder와 advanced packaging 장비 관점에서 Tier S/A 후보로 볼 수 있고, BESI·ASMPT는 bonding/hybrid bonding 쪽 source-pack 후보로 둔다. KLA, Onto Innovation, Camtek, IntekPlus는 inspection/metrology, ISC와 Leeno Industrial은 test socket/probe, HPSP·Wonik IPS·Applied Materials·Lam Research·ASM International은 process/WFE derivative enabler로 본다. 단, 한국 장비 proxy는 수주잔고, 고객 qualification, 양산 전환, margin, OP/EPS revision이 붙기 전까지 Tier 상향을 보류한다.

Power·cooling·grid와 capex ROI gate에서는 Vertiv, Eaton, Schneider Electric, Quanta Services, GE Vernova, Constellation Energy가 public infrastructure 후보이고, NuScale/Oklo/BWXT류 SMR·nuclear option은 더 긴 시간축의 관찰 후보로 둔다. Vertiv는 liquid cooling/rack power/backlog가 확인될 때 Tier S/A 후보가 될 수 있고, Eaton·Schneider·GE Vernova·Quanta는 transformer/switchgear/grid EPC/energy management의 Tier A 후보로 본다. 한국 proxy는 HD Hyundai Electric, LS ELECTRIC, Hyosung Heavy Industries, Iljin Electric, Sanil Electric, Doosan Enerbility, Samsung SDS다. 이 레이어의 핵심은 “전력 수혜”라는 말이 아니라 transformer/switchgear/PDU/UPS/busway/liquid cooling/CDU/backlog/lead time/PPA/grid interconnect/site permitting evidence다.

Optical/networking·AI storage와 robotics/on-device gap에서는 Arista Networks, Broadcom, Marvell, Cisco, Ciena, Coherent, Lumentum, Corning이 optical/networking public 후보로 남는다. Lightmatter, Ayar Labs, Celestial AI는 photonic interconnect와 optical I/O wall의 비상장 S-watch 후보지만, design win과 shipment 전에는 public proxy로 번역하지 않는다. AI storage lifecycle에서는 Seagate, Western Digital, Sandisk, FADU, Micron, Samsung Electronics, SK Hynix가 후보지만, storage는 GPU/HBM bottleneck breaker가 아니라 데이터 lifecycle의 Tier B 또는 조건부 Tier A에 가깝다. Robotics/on-device에서는 NVIDIA, Arm, Qualcomm, Apple, Teradyne, Rockwell Automation, Tesla, Intuitive Surgical, Stryker, Rainbow Robotics, Doosan Robotics, Hyundai Mobis를 관찰할 수 있으나, 이번 주 Reuters 신호를 기준으로는 factory deployment, order, uptime, safety certification이 확인되기 전까지 대다수는 Tier B/C다.

5. 공개주 / 비상장 / 한국 proxy

Cloud demand translator는 Microsoft, Amazon, Alphabet, Meta, Oracle, CoreWeave, Nebius이며, 이들은 병목 breaker라기보다 capex와 workload를 실제 수요로 번역하는 쪽이다. Data/platform/security는 Cloudflare, Datadog, CrowdStrike, Palo Alto Networks, ServiceNow, Snowflake, MongoDB다. Power/cooling/grid는 Vertiv, Eaton, Schneider Electric, Quanta Services, GE Vernova, Constellation Energy다. Optical/networking은 Arista, Cisco, Ciena, Coherent, Lumentum, Broadcom, Marvell이다. Storage는 Seagate, Western Digital, Sandisk, Micron이다. 이 모든 proxy는 가격 방향이 아니라 어떤 병목을 깨거나 측정하거나 운영하는지로만 본다.

6. 다음 주 확인할 것

다음 주 첫 번째 확인은 agent production gate다. FrontierChallenge, Agentic Game Development, What Makes Good Agentic Data?, TaoLive Harness류의 신호가 제품 release note에서 trace/replay, sandbox, permission boundary, workflow artifact, partial-success evaluation, failure recovery, red-team, enterprise admin control로 반복되는지 본다. 단순 benchmark 점수와 데모 영상은 부족하다.

두 번째는 memory/RAG provenance와 inference economics다. RetrievalRouter, WeMM-Embedding, CaSKG, CritICL류의 신호가 access-control-aware retrieval, citation/provenance, memory hygiene, cache invalidation, KV-cache compression/offload, lower serving cost per task, longer session length, tool-call volume 증가로 이어지는지 확인한다. 비용 절감이 총 compute demand를 줄이는지, 아니면 사용량을 키우는지도 분리해야 한다.

세 번째는 HBM/advanced packaging/test의 hard evidence다. SK Hynix의 Indiana timing과 shortage-through-2030 신호가 HBM3E/HBM4 qualification, yield, shipment, bit shipment, ASP, CoWoS capacity, TC/hybrid bonding backlog, inspection/metrology order, test socket demand로 반복되는지 확인한다. Samsung Electronics는 HBM catch-up과 legacy DRAM/NAND, foundry/System LSI drag, MX/mobile, capital return, foreign flow, EPS revision을 분리해서 본다.

네 번째는 hyperscaler capex ROI와 physical infra order다. Reuters의 capex angst fade 신호가 AWS/Azure/GCP/Meta/Oracle/CoreWeave의 AI usage, utilization, AI revenue contribution, RPO/commitment conversion, gross margin, FCF, depreciation 부담 완화로 확인되는지 본다. 동시에 Vertiv/Eaton/Schneider/GE Vernova/Quanta/한국 전력장비 proxy의 order, backlog, lead time, data-center customer mix, margin conversion이 붙는지 확인한다.

다섯 번째는 optical/networking·AI storage다. 800G/1.6T optics, AI Ethernet switching, custom ASIC networking revenue, optical DSP, silicon photonics design win, nearline exabytes, Data Center storage mix, eSSD design-win, HAMR/Mozaic ramp, SSD controller qualification이 반복되는지 본다. Storage는 AI data lifecycle 수혜일 수 있지만, GPU/HBM 병목을 직접 깨는 회사처럼 과장하지 않는다.

여섯 번째는 robotics/on-device의 demo-to-production gap이다. Reuters의 factory-use gap처럼 humanoid/robot signal은 데모가 많을수록 오히려 production evidence를 더 엄격히 봐야 한다. 제품 출하, 공장 deployment, uptime, safety certification, service revenue, edge NPU/SoC attach-rate, AI PC/mobile 사용량, on-device runtime adoption이 없으면 핵심 병목이 아니라 관찰 후보로 둔다.

일곱 번째는 geopolitics/export-control이다. Nvidia, Vera Rubin cluster, sovereign AI, China substitution, regional data center build-out, export license/enforcement가 GPU/HBM/packaging 공급과 고객 접근성을 어떻게 바꾸는지 본다. 정책 headline만으로 Tier를 조정하지 않고, license, shipment, order cancellation, regional capex relocation이 확인될 때만 반영한다.

7. 판단의 약점

첫 번째 약점은 market data freshness의 비대칭이다. AI research는 2026-08-30까지 반영했지만, 최신 완전 market/cross report는 2026-08-28이다. 2026-08-30 exact market-sources는 price-only 성격이 강해 이번 주 시장 narrative 판단의 핵심 근거로 쓰지 않았다. 따라서 이 보고서는 전 세계 1주일 전체 뉴스를 완전 조사한 리포트가 아니라 Research Desk의 최신 local signal 기반 scenario planning이다.

두 번째 약점은 adoption evidence 미확인이다. Agentic AI, post-training, RAG, inference 논문이 반복된다고 해서 enterprise paid deployment나 cloud workload 증가가 확인된 것은 아니다. Cross edge는 관심도와 recognition gap을 표시할 뿐, usage·계약·출하·운영 로그·매출 전환 근거가 없으면 시장 연결은 보류해야 한다.

세 번째 약점은 market source quality의 혼재다. Reuters, WSJ, Bloomberg, Financial Times 같은 근거가 있지만, power/SMR/on-device/healthcare/robotics 기사에는 보조·저신뢰 source가 섞여 있다. 고품질 source가 반복되기 전까지 narrative heat는 evidence가 아니라 routing proxy다.

네 번째 약점은 verified sell-side revision history 확인 필요다. 회사별 price/EPS/consensus revision tape가 완전히 연결되지 않았기 때문에 “가격에 덜 반영됐다”거나 “이미 반영됐다”는 식의 강한 결론은 금지한다. 가격 데이터가 없거나 불완전한 곳은 확인 필요로 표기하고, brokerage/IR/filing/source-pack 검증 전에는 판단 보류다.

다섯 번째 약점은 public proxy와 실제 bottleneck breaker가 다를 수 있다는 점이다. Agent runtime, eval, RAG security, inference scheduling, photonic interconnect는 비상장 또는 오픈소스가 실제 bottleneck breaker일 수 있다. 상장사는 indirect proxy일 수 있으므로 public ticker만으로 병목 해결력을 과장하면 narrative beta가 된다.

여섯 번째 약점은 robotics/on-device와 storage thesis의 과장 위험이다. Robotics는 데모와 factory deployment 사이의 gap이 크고, storage는 AI data lifecycle의 중요한 보조 병목이지만 GPU/HBM 병목을 직접 푸는 레이어는 아니다. 이번 주 Base에서는 둘을 관찰 후보로 유지하되, core bottleneck breaker로 승격하려면 order, deployment, exabyte, design-win, revenue conversion이 필요하다.

8. 8~12주 플래닝 전략

이번 8~12주 운영 순서는 시나리오 유지/폐기 → 병목 강화/약화 → Tier 조정 → 다음 검증 질문이다. 회사는 항상 마지막에 둔다.

  • Root hypothesis: Agentic AI가 실제 업무·과학 workflow·personal agent·enterprise workflow·robotics/on-device 환경으로 확장될수록 verifiable trajectory, evaluation harness, memory/RAG provenance, permissioned runtime, KV-cache/inference economics가 먼저 병목이 된다. 이 software gate가 해결될수록 long-context session, tool-call log, retrieval cache, storage/audit archive, cloud workload가 늘고, downstream으로 HBM/DRAM, advanced packaging/test, data-center power/cooling/grid, optical/networking, AI storage lifecycle 병목이 강화된다. 시장은 broad AI narrative보다 hard evidence가 붙은 bottleneck breaker와 narrative beta를 분리한다.
  • Confirm trigger: Base가 강해지려면 최소 2~3개 layer에서 hard evidence가 동시에 확인되어야 한다. Agent 쪽은 paid workflow, tool-call volume, workflow retention, trace/replay/sandbox/permission release, security incident absence가 필요하다. RAG/memory 쪽은 provenance, audit, compliance pilot, access-control-aware retrieval adoption이 필요하다. Cloud 쪽은 AI usage, utilization, AI revenue contribution, RPO/commitment conversion, margin, FCF 회복 언어가 필요하다. Semiconductor 쪽은 HBM qualification, CoWoS throughput, bonding/metrology order, test socket demand가 필요하다. Physical infra 쪽은 transformer/switchgear/liquid cooling/rack power backlog와 lead time이 필요하다. Optical/storage 쪽은 800G/1.6T shipment, custom silicon networking revenue, eSSD design-win, nearline exabytes가 필요하다.
  • Invalidation trigger: Agent research가 benchmark·demo에 머물고 enterprise workflow evidence가 없거나, memory/RAG failure와 security incident가 늘거나, hyperscaler가 capex ROI·FCF 부담을 공식화하고 AI revenue contribution이 약하거나, HBM/packaging/power/optical/storage 증거가 headline에 머물면 Base를 약화한다. 이 경우 Downside인 AI capex fatigue + production gate failure로 전환한다. 반대로 agent production adoption과 물리 병목 order가 동시에 붙으면 Upside로 전환하되, 그때도 회사 리스트가 아니라 bottleneck breaker evidence부터 다시 쓴다.
  • Tier 상향 조건: Tier B/C 후보는 고객 채택, production reference, order/backlog, qualification, yield/throughput, 반복 매출, margin, verified EPS/consensus revision evidence가 붙을 때만 Tier S/A로 올린다.
