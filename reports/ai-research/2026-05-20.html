2. 한눈에 보는 오늘의 AI Research 지도

목적: 항목 나열 전에 능력 향상 → agent화 → orchestration/inference 병목 → edge 이동 → 신뢰성 리스크 흐름을 먼저 본다.
flowchart LR Post_training["Post-training"] -- improves --> Agentic_AI["Agentic AI"] Agent_Planning["Agent Planning"] -- controls --> Agentic_AI["Agentic AI"] Tool_Use___MCP["Tool Use / MCP"] -- connects --> Agentic_AI["Agentic AI"] Agentic_AI["Agentic AI"] -- becomes --> Personal_Agent["Personal Agent"] Agent_Evaluation["Agent Evaluation"] -- validates --> Agentic_AI["Agentic AI"] Agent_Security["Agent Security"] -- constrains --> Personal_Agent["Personal Agent"] LLM_Orchestration["LLM Orchestration"] -- turns_models_into --> Agentic_AI["Agentic AI"] Inference_Stack["Inference Stack"] -- makes_feasible --> Agentic_AI["Agentic AI"] Inference_Stack["Inference Stack"] -- enables --> On_device_LLM["On-device LLM"] On_device_LLM["On-device LLM"] -- moves_workloads_to --> Edge_AI["Edge AI"] Agentic_AI["Agentic AI"] -- requires --> Memory___RAG["Memory / RAG"] Memory___RAG["Memory / RAG"] -- introduces_risk --> RAG_Security["RAG Security"] LLM_Orchestration["LLM Orchestration"] -- uses_protocols_like --> MCP["MCP"]

지도 읽는 법 — 한글 설명

  • Post-training → Agentic AI: 보상/검증/정렬 방식이 좋아지면 agent가 더 긴 작업을 안정적으로 수행할 가능성이 커진다.
  • LLM Orchestration → Agentic AI: 모델 하나의 성능보다 도구 호출, routing, workflow 설계가 실제 agent 제품화의 핵심 병목이 된다.
  • Inference Stack → Agentic AI / On-device LLM: latency, memory, serving cost가 낮아져야 agent와 local AI가 일상적으로 쓰인다.
  • Agentic AI → Memory/RAG → RAG Security: agent가 기억과 검색을 쓰기 시작하면 정확성은 좋아질 수 있지만, 검색 오염과 evidence 추적 문제가 같이 커진다.
