Prediction Feedback Loop

Research Desk의 예측 layer는 단순 rule-based alert가 아니다. 단기/중장기 예측 → 실제 관찰 → timing gap 분석 → 다음 예측 보정으로 강해지는 feedback system이다.
Short 1일~2주 · news flow와 node heat가 바로 강화/약화되는지 확인
Mid 1개월~1분기 · adoption, infra integration, enterprise risk 확인
Long 6개월~2년 · structural theme와 산업 edge 지속성 확인

핵심 문제

AI 기술 집중 관심도와 시장 반응은 같은 시점에 움직이지 않을 수 있다.

그래서 이 시스템은 단순히 “오늘 signal이 강하다”에서 끝나면 안 된다.

각 signal이 언제 시장 narrative로 번역될지, 또는 이미 시장이 먼저 반응했는데 기술 evidence가 따라오고 있는지를 매번 체크해야 한다.

예측 horizon

Short-term · 1일 ~ 2주

  • 오늘/이번 주 signal이 바로 어떤 narrative를 강화/약화하는지 본다.
  • Telegram daily brief와 Cross Signal에서 사용한다.
  • 예: Inference memory/cost signal이 이번 주 AI data center/power narrative와 같이 움직이는가?

Mid-term · 1개월 ~ 1분기

  • 기술 signal이 제품화, enterprise adoption, infra demand로 이어지는지 본다.
  • Weekly/Monthly synthesis에서 사용한다.
  • 예: Agent memory/RAG security가 enterprise AI adoption 병목으로 반복 등장하는가?

Long-term · 6개월 ~ 2년

  • structural theme, supply chain, industry edge의 지속성을 본다.
  • Quarterly review와 public essay 후보에 사용한다.
  • 예: On-device LLM은 cloud inference demand를 대체하는가, 아니면 edge workload를 새로 만드는가?

Forecast Loop

flowchart LR Signal["Daily Signals"] --> Forecast["Prediction Ledger"] Forecast --> Watch["Trigger Watch"] Watch --> Actual["Actual Outcome"] Actual --> Gap["Gap Analysis"] Gap --> Update["Assumption / Weight Update"] Update --> Forecast

세 가지 score를 분리해서 본다

  • Technical attention score: 논문, 레포, HN/GitHub/HF/arXiv 집중도
  • Adoption evidence score: 제품화, enterprise 사용, infra integration, benchmark-to-product 전환
  • Market narrative score: 뉴스, 가격, capex, company mention, analyst/industry narrative

중요한 건 점수 하나가 아니라 세 score의 시간차와 방향성이다.

technical ↑ / market 아직 약함
→ early signal 후보

market ↑ / technical 약함
→ hype 또는 선반영 후보

technical ↑ / adoption ↑ / market ↑
→ reinforced trend

technical ↓ / market ↑
→ narrative fragility 후보

Timing Gap 유형

1. Technical Leads Market

기술 signal이 먼저 나오고 market narrative가 나중에 반응하는 경우.

  • 예: RAG security / agent memory 논문·레포 증가
  • 몇 주 뒤: enterprise AI governance, healthcare AI risk narrative 증가

2. Market Leads Technical

시장이 먼저 과열되고 기술 evidence가 나중에 따라오거나 실패하는 경우.

  • 예: robotics/humanoid narrative 급등
  • 실제 on-device model, sensor, actuator, deployment evidence는 약함

3. Simultaneous Reinforcement

기술 signal과 시장 narrative가 같은 주에 같이 강해지는 경우.

  • 예: inference memory/cost 논문 증가
  • 동시에 data center/power/capex 뉴스 증가

4. Decoupling / Blind Spot

기술 signal은 강하지만 시장은 무시하거나, 시장은 강하지만 기술 evidence가 비어 있는 경우.

  • 가장 중요한 alert 후보
  • dashboard에서는 Mismatch / Blind Spot 카드로 표시

Prediction Ledger에 남겨야 할 것

각 예측은 방향만 쓰지 않는다. 아래를 같이 저장한다.

  • 예측 내용
  • short / mid / long horizon
  • 연결된 research node
  • 연결된 market node
  • time lag assumption
  • confidence
  • evidence for / against
  • trigger to watch
  • invalidation condition
  • expected check date
  • actual outcome
  • gap analysis
  • model update

이 시스템의 목적

목표는 매번 맞히는 것이 아니다.

목표는:

틀린 예측을 지우지 않고
왜 틀렸는지 남기고
다음 예측의 가정과 가중치를 바꾸는 것

즉, Research Desk는 시간이 지날수록 다음을 학습한다.

  • 어떤 source가 noise였는가
  • 어떤 signal이 market으로 늦게 번역되는가
  • 어떤 narrative가 기술 evidence 없이 먼저 과열되는가
  • 어떤 edge가 반복적으로 실제 outcome과 맞는가
