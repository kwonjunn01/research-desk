Narrative Impact Transmission Model

AI narrative/context가 산업 수요와 시장 narrative로 전파되는 경로를 추적하는 공개 요약 페이지. 투자 추천이 아니라 Research Desk의 예측/검증 프레임워크다.

핵심 아이디어

대박 후보는 단순히 “좋은 AI 기술”이 아니다.

좋은 AI 기술이 실제 workflow로 들어가고 → workload를 만들고 → bottleneck을 만들고 → 누군가 돈을 쓰고 → 시장이 뒤늦게 그 산업/기업으로 번역하는 순간이 중요하다.

전파 체인

flowchart LR A["Technical Legitimacy<br/>연구/산업에서 이건 된다"] --> B["Workflow Adoption<br/>실제 업무/제품에 들어감"] B --> C["Workload Translation<br/>token/context/session/memory 증가"] C --> D["Bottleneck Formation<br/>HBM/DRAM/GPU/power/security"] D --> E["Buyer / Capex Recognition<br/>hyperscaler/enterprise/OEM 지출"] E --> F["Market Narrative Recognition<br/>애널리스트/뉴스/섹터 narrative"] F --> G["Price / Revision Reaction<br/>주가/추정치/traffic light 반영"]

우리가 잡고 싶은 것은 마지막 주가 반응이 아니라, 초기 1~4단계에서 5~7단계로 넘어갈 후보다.

Agent AI → DRAM/HBM 예시

Agent AI가 단순 챗봇을 넘어 실제 workflow로 인정받으면 다음 수요 단위가 생긴다.

  • 더 긴 context와 planning trace
  • persistent memory와 retrieval/cache
  • 더 많은 tool call과 multi-step inference
  • observability/logging/security/audit trail
  • concurrent agent session 증가

이것은 AI server memory, HBM, server DRAM, storage/network, data center power/cooling narrative로 번역될 수 있다.

그래서 사후적으로는 다음 체인이 보인다.

Agent AI legitimacy
→ workflow automation adoption
→ inference/context/session explosion
→ HBM/DRAM/AI server bottleneck
→ hyperscaler/server capex & memory demand
→ Samsung/SK Hynix/Micron narrative
→ price/revision reaction

Research Desk가 노리는 건 “삼성전자가 오른 뒤 설명”이 아니라, agent workflow가 인정되고 memory bottleneck으로 번역되기 시작하는 초기 시점이다.

Early Signal 조건

Technical Legitimacy ↑
+ Adoption Translation ↑
+ Workload/Bottleneck 명확
+ Market Recognition 아직 약함
= Early Cross-Ontology Candidate

AI-native 차별점

Narrative Drift

demo excitement
→ workflow automation
→ inference workload
→ memory bottleneck
→ capex/order cycle
→ earnings revision

Context-to-Demand Translation

키워드를 바로 종목에 붙이지 않고, 먼저 어떤 수요 단위로 번역되는지 본다.

  • token volume
  • context length
  • concurrent sessions
  • memory bandwidth
  • HBM stack 수요
  • server DRAM content
  • power/cooling/network
  • compliance/security tooling

Recognition Gap

가장 중요한 구간은 시장이 아직 번역을 덜 한 상태다.

  • 연구/개발자 attention은 강하지만 market article은 약함
  • product adoption은 보이지만 supplier narrative는 약함
  • bottleneck은 명확하지만 공급자 실적/추정치 반영은 약함

Contradiction Map

항상 반대근거를 붙인다.

  • Agent AI가 production usage를 못 만들 수 있다.
  • model efficiency/on-device가 cloud memory 수요를 줄일 수 있다.
  • 이미 주가와 valuation에 선반영됐을 수 있다.
  • 공급 증가나 가격 하락이 수요 증가를 상쇄할 수 있다.

현재 감시 후보

오늘의 강력 관찰 후보 1~2개 운영

매일 1~2개만 올린다. 추천이 아니라 초기 narrative/context 후보다. 며칠간 같은 후보가 반복돼도 된다. 반복은 그만큼 강한 내러티브일 수 있다.

각 후보는 반드시 아래를 포함한다.

  • 왜 지금인지
  • 예상 전파: research signal → workload → bottleneck → solver/company/sector → market recognition
  • 핵심 병목
  • 누가 해결 중인지
  • 초기 탑승 논리: 시장이 아직 덜 번역한 부분
  • 다음 확인 trigger
  • 틀릴 조건

우선 감시 후보

  • Agent AI → inference/session/context explosion → HBM/DRAM/AI server memory
  • Agent browser/computer use → browser runtime/proxy/CDN/anti-bot/observability traffic
  • Long-context / memory agents → storage/vector DB/observability/security
  • Computer-use agents → enterprise desktop/cloud ops automation → governance/security spend
  • On-device personal agents → mobile/edge NPU, local memory, privacy workflow
  • AI coding agents → devtool/cloud compute consumption, CI/test workload, enterprise seat expansion

Agent Browser Traffic 가설

“Agent AI가 브라우징을 수십 번 하면 인터넷 트래픽이 수십 배 늘지 않을까?”는 좋은 early hypothesis다. 다만 전체 인터넷 트래픽이 바로 수십 배로 뛴다고 보기보다, 먼저 더 작은 demand unit으로 쪼갠다.

가능한 전파

Agent browser/computer use adoption
→ task당 page load / request / screenshot / DOM extraction 증가
→ proxy, browser runtime, anti-bot, CDN, network, observability load 증가
→ agent infra / web automation / security / monitoring solver 수요 증가

반대 가능성

Agent browsing 비용/지연/차단 과다
→ production에서는 API, MCP, cached search, structured data feed로 우회
→ 일반 인터넷 트래픽보다 agent-specific infra와 permission layer가 더 중요

그래서 확인할 것은 “인터넷 전체 트래픽”보다 다음이다.

  • agent task당 browser call 수
  • browser-use agent 제품의 latency/cost complaint
  • proxy/CDN/anti-bot vendor의 AI agent traffic 언급
  • Cloudflare/Akamai/Fastly/Zscaler/Datadog/Browserbase류의 agent traffic narrative
  • MCP/API 우회가 browsing traffic을 줄이는지 여부

Bottleneck-Solver Lens

좋은 예측은 “무엇이 뜬다”보다 무엇이 막히고, 누가 그걸 해결하는가에서 나온다.

  • Compute: GPU, inference accelerator, serving stack, batching, quantization
  • Memory: HBM, server DRAM, KV cache, long context, retrieval cache
  • Network/browser: browser-use agent, crawling, proxy, CDN, anti-bot, latency, bandwidth
  • Power/cooling: grid, transformer, cooling, data center siting
  • Trust/security: identity, permission, audit, RAG poisoning, observability
  • Workflow: integration, approvals, UI automation, enterprise procurement

운영 원칙

AI narrative가 주식에 영향을 주는지 묻기보다, 그 narrative가 어떤 workload와 bottleneck으로 번역되고, 누가 돈을 쓰며, 시장이 그 번역을 아직 놓치고 있는지를 추적한다.
