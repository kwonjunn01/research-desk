Agent AI Specialist Map

Agent AI를 하나의 buzzword로 보지 않고, 기술 stack → personal agent → 병목 → cross-market lane → 매일 점검 질문으로 쪼개 보는 전문 리서치 지도.
Specialist Layers

9개 layer를 매일 추적: model, planning, tool, memory, browser, runtime, eval, security, personal product

Bottlenecks

8개 핵심 병목: reliability, tool error, memory, permission, eval gap, cost/latency

Cross-Market Lanes

5개 lane으로 inference/data center/security/edge/AI DevOps narrative와 연결

각 layer는 매일 수집된 논문/레포/뉴스/제품 업데이트가 어느 위치에서 나왔는지 분류하는 기준이다.

3. Specialist lens cards

Model & Reasoning

  • reasoning model, structured output, function calling reliability가 agent task success의 출발점이다.
  • Daily watch: reasoning quality, tool/function calling, latency
  • Keywords: reasoning, function calling, structured output, o3, claude

Planning & Control

  • agent가 demo를 넘어 장기 작업을 수행하려면 decomposition, validation, replanning이 필요하다.
  • Daily watch: task decomposition, plan validation, replanning
  • Keywords: planning, replanning, long-horizon, decomposition, react

Tool Use / MCP

  • MCP, function calling, tool registry가 agent를 실제 업무 시스템과 연결한다.
  • Daily watch: MCP ecosystem, tool discovery, schema validation
  • Keywords: mcp, model context protocol, tool server, function calling, tool registry

Memory / RAG

  • personal agent에는 장기 기억과 evidence trace가 필요하지만 context pollution과 privacy risk가 커진다.
  • Daily watch: long-term memory, graph memory, retrieval precision
  • Keywords: memory, rag, retrieval, graph memory, context

Browser / Computer Use

  • browser/computer use는 personal agent의 행동 범위를 넓히지만 UI drift와 승인 경계가 병목이다.
  • Daily watch: browser automation, computer use, UI drift
  • Keywords: browser, computer use, operator, gui, screen

Runtime / Ops

  • 장기 실행 agent는 state persistence, checkpoint, trace, scheduler가 없으면 운영 시스템이 되지 못한다.
  • Daily watch: state store, checkpoint, resume
  • Keywords: workflow, runtime, state, checkpoint, scheduler

Eval / Observability

  • SWE-bench/WebArena/GAIA 같은 benchmark와 실제 사용성 gap을 계속 추적해야 한다.
  • Daily watch: task success rate, step error rate, cost per task
  • Keywords: eval, benchmark, swe-bench, webarena, gaia

Security / Trust

  • prompt injection, tool abuse, permission, secret leakage는 personal/enterprise agent adoption의 핵심 병목이다.
  • Daily watch: prompt injection, permission scope, secret leakage
  • Keywords: prompt injection, permission, sandbox, secret, audit

Personal Agent Product

  • 사용자에게 중요한 것은 chatbot이 아니라 email/calendar/browser/files/local memory를 다루는 recurring workflow다.
  • Daily watch: email/calendar, files/notes, browser tasks
  • Keywords: personal agent, email, calendar, files, assistant

7. Agent AI → Market / Cross-Ontology Lanes

Agent AI 신호는 기술 뉴스로 끝나지 않고 inference, data center, security, SaaS, edge AI narrative로 이어질 수 있다.

flowchart LR A1["Agent workload 증가"] --> M1["Inference Stack / Data Center"] A2["Memory/RAG 확산"] --> M2["Vector DB / Storage / Security"] A3["Browser/Computer Use 확산"] --> M3["SaaS workflow / RPA / Identity"] A4["On-device personal agent"] --> M4["Edge AI / Device / Privacy"] A5["Eval/Observability 중요도 상승"] --> M5["AI DevOps / Monitoring"]
  • Agent workload 증가 → Inference Stack / Data Center: agent가 task당 token/tool/browser call을 늘리면 inference demand와 data center narrative가 강화되는가?
  • Memory/RAG 확산 → Vector DB / Storage / Security: enterprise agent memory가 storage, retrieval, security tooling 수요를 만드는가?
  • Browser/Computer Use 확산 → SaaS workflow / RPA / Identity: 기존 SaaS/RPA/ID permission layer와 경쟁·보완 관계가 어떻게 바뀌는가?
  • On-device personal agent → Edge AI / Device / Privacy: local inference와 privacy가 device/edge AI narrative로 이어지는가?
  • Eval/Observability 중요도 상승 → AI DevOps / Monitoring: agent production incident가 eval/observability tooling 수요를 당기는가?

8. Daily Agent AI Specialist Watch

Daily AI Research Radar는 매일 아래 질문을 확인한다.

  1. 오늘 신호는 어느 layer에서 나왔는가?
  2. 실제 personal agent를 더 쓸모 있게 만드는가, 아니면 demo hype인가?
  3. 어떤 병목을 직접 건드리는가?
  4. 새 node/edge로 ontology에 추가해야 하는가?
  5. user-facing product 변화인가, infra/framework 변화인가?
  6. 내가 모르고 있던 unknown은 무엇인가?
  7. market/cross ontology로 이어질 edge가 있는가?
  8. prediction ledger에 올릴 만한 timing-gap claim인가?
