Quant Strategy Council

목적: 단일 Strategy Bot이 혼자 판단하지 않고, 에이전트 팀이 전략 회의를 통해 현재 구조의 리스크를 줄이고 장세별 전략 스위치를 결정한다.

1. 회의 원칙

Strategy Council은 매번 “무엇을 살까?”보다 먼저 “지금 이 전략을 켜도 되는 장인가?”를 묻는다.

Risk First

수익률보다 청산 확률, margin buffer, tail-risk를 먼저 검토

Regime Switch

횡보/추세/이벤트/유동성 장세별로 전략 모드를 다르게 선택

Context Aware

차트뿐 아니라 사회상황, 기술 이슈, 규제/매크로, 거래소 리스크를 함께 반영

2. 회의 참여 Agent

  • Portfolio Manager Agent
  • 현재 전략 자본, 손실 한도, exposure budget 결정
  • Strategy Bot
  • 무한매수법 v2 기본 intent 생성
  • 전략 스위치 후보 제안
  • Risk Bot
  • margin, liquidation buffer, gap risk, kill-switch 조건 검토
  • Scenario Planning Agent
  • black swan, macro/social/technology issue, exchange risk 시나리오 제시
  • Research / Alpha Agent
  • 뉴스, 정책, 기술, 온체인/시장 구조 변화 맥락 수집
  • Validator Agent
  • 후보 전략이 과최적화인지, 백테스트/리플레이 근거가 충분한지 반박
  • Reporting Agent
  • 결정과 근거를 Research Desk에 남김

3. 회의 안건

각 회의는 아래 순서로 진행한다.

1. Current Position Review
2. Market Regime Review
3. External Context Review
4. Scenario Planning
5. Strategy Switch Decision
6. Risk Budget / Margin Check
7. Action Plan
8. Rejected Alternatives 기록

4. 현재 전략 기준

기본 전략은 BTC Futures 무한매수법 v2다.

  • 20x display leverage
  • first notional: capital × 20 × 0.5 / 31
  • 1-2-4-8-16 5단계
  • 1% 하락마다 다음 stage 1개만 pending
  • 평단 +0.5% 전체 익절
  • Risk Bot은 추가매수만 중단/재개

이 기본 골격은 회의 없이 즉흥적으로 바꾸지 않는다.

5. Strategy Switch Matrix

장세별로 전략 모드를 다르게 선택한다.

  • Range / Mean-Reversion Friendly
  • 조건: ADX 낮음, lower breakdown 없음, funding/뉴스 리스크 낮음
  • 모드: 무한매수법 v2 ACTIVE
  • 행동: stage1 진입, gate ON이면 다음 stage 1개 pending
  • Transition / Unclear
  • 조건: 방향성 불확실, 이벤트 대기, 지표 혼재
  • 모드: HOLD_EXISTING / NO_NEW_STAGE
  • 행동: 보유 포지션 TP 유지, 신규 추가매수 제한
  • Trend Down / Breakdown Risk
  • 조건: ADX rising, lower-band breakdown, 매크로/뉴스 악재
  • 모드: ADD_BUY_OFF
  • 행동: 남은 pending buy 취소, 기존 TP만 유지
  • Event / Black-Swan Watch
  • 조건: 전쟁/규제/거래소 장애/ETF·금리·CPI/FOMC 등 이벤트
  • 모드: PAUSE_OR_REDUCE
  • 행동: 신규 stage 금지, 필요시 manual review
  • Data / Exchange Degradation
  • 조건: stale data, last-mark divergence, API timeout
  • 모드: DATA_NOT_READY
  • 행동: 신규 intent 금지, alert/report

6. Context Inputs

차트만 보지 않는다. Strategy Council은 아래 맥락을 같이 본다.

  • Macro:
  • FOMC, CPI, 금리, 달러, 유동성
  • Crypto market structure:
  • funding, basis, open interest, liquidation cluster, ETF flow
  • Social / geopolitical:
  • 전쟁, 규제, 대형 거래소 이슈, 법원/정책 이벤트
  • Technology / security:
  • 체인 장애, 해킹, bridge exploit, L2/ETF/infrastructure 이슈
  • Exchange / execution:
  • OKX data health, mark/last divergence, funding abnormality, API degradation
  • Narrative:
  • BTC dominance, AI/tech risk-on/off, market sentiment shift

7. Decision Output

회의 결과는 아래 형태로 남긴다.

{
  "decision": "ADD_BUY_OFF",
  "strategy_mode": "infinite_buy_v2_hold_existing",
  "reason": ["ADX rising", "macro event within 24h", "funding abnormal"],
  "allowed_actions": ["keep_tp", "cancel_pending_buys"],
  "blocked_actions": ["new_stage", "increase_leverage"],
  "review_after": "next_4h_or_event_resolution"
}

8. Anti-Spaghetti Rule

회의에서 나온 아이디어는 바로 Strategy Bot 코드에 if문으로 추가하지 않는다.

scenario → hypothesis → replay/backtest → validator review → candidate → paper → promote/reject

전략 스위치는 agent team의 합의와 검증 로그를 따라야 한다.
