Quant Bot Upgrade Roadmap

현재 Quant Bot의 다음 목표는 “수익 나는 규칙 하나”가 아니라, 전략 회의·맥락 기반 시나리오·리스크 엔진·검증·운영 자동화가 분리된 시스템으로 업그레이드하는 것이다.

Current Baseline

Canonical Strategy

BTC Futures 무한매수법 v2: 20x, 1-2-4-8-16, 1% add-buy, avg+0.5% TP

Paper Only

OKX public data only. private/trading API 미사용. live_orders_allowed=false

Next Goal

Risk Engine 2.0 + Strategy Council + Context Scenario + Replay Validator

현재 기준:

  • Market: OKX public BTC-USDT-SWAP
  • Capital: 2035 USDT paper
  • Margin: strategy subaccount 내부 cross-margin model
  • First notional: capital × 20 × 0.5 / 31
  • Stage: 1-2-4-8-16
  • Add-buy: 1% 하락마다 다음 stage 1개만
  • TP: avg entry +0.5% full close
  • Safety: 실거래 off

Upgrade Pillars

1. Risk Engine 2.0

목표: “언제 더 사면 안 되는가”를 더 정확하게 판단한다.

구현할 것:

  • Mark Price 기반 liquidation/margin ratio 개선
  • fee/funding/slippage 포함 equity tracking
  • stage별 liquidation buffer 계산
  • margin ladder: 50/60/70% warning/cancel/reduce candidate
  • gap-down stress: -3%, -5%, -8%, -12%
  • pending buy cancellation latency simulation

성공 기준:

  • stage별 liq_buffer_pct, free_equity, margin_proxy, max_add_allowed가 ledger에 남는다.
  • Risk Bot이 profitable candidate도 청산 리스크가 커지면 reject한다.

2. Context-Aware Scenario Engine

목표: 차트만 보지 않고 시장 맥락을 같이 본다.

입력:

  • Macro: FOMC, CPI, rates, DXY, liquidity
  • Crypto structure: funding, basis, OI, ETF flow, liquidation clusters
  • Social/geopolitical: war, regulation, risk-off panic
  • Tech/security: chain halt, exploit, bridge/custody issue
  • Exchange health: OKX stale data, mark-last divergence, timeout
  • Narrative: BTC dominance, AI/tech risk-on/off

출력 예시:

{
  "scenario_mode": "EVENT_PAUSE",
  "severity": "medium_high",
  "context": ["FOMC within 24h", "funding abnormal"],
  "allowed_actions": ["keep_tp", "no_new_stage"],
  "blocked_actions": ["new_stage", "increase_leverage"]
}

3. Strategy Council / Regime Switch

전략은 장마다 다르게 켜고 끈다. 이 결정은 단일 indicator가 아니라 agent team 회의 결과를 따른다.

모드:

  • ACTIVE_INFINITE_BUY_V2
  • HOLD_EXISTING_NO_NEW_STAGE
  • ADD_BUY_OFF
  • EVENT_PAUSE
  • DATA_NOT_READY

필요 구현:

  • scripts/run_strategy_council.py
  • latest state + features + scenario context 입력
  • council decision JSONL 출력
  • rejected alternatives 기록

4. Backtest / Replay / Validator Stack

목표: 전략 변경은 감이 아니라 replay와 독립 검증을 통과해야 한다.

구현할 것:

  • paper ledger replay engine
  • historical OKX candles/mark/funding storage
  • stage fill simulator
  • fee/funding/slippage model
  • no-lookahead validator
  • OOS/walk-forward runner
  • rejected candidate ledger

승격 경로:

candidate → shadow → paper_canary → paper_primary → live_candidate → live_approved

live_approved는 사용자 승인 전까지 불가능하다.

5. Rust Time-Series Forecast Core

Python은 orchestration, Rust는 무거운 시계열 계산을 담당한다.

Rust 역할:

  • rolling indicators
  • volatility expansion probability
  • lower-band breakdown risk
  • tail move score
  • funding/basis stress score
  • walk-forward parameter sweep

금지:

  • forecast 단독 live order
  • forecast 단독 leverage cap 완화
  • 검증 없는 profile 변경

6. Operations / Reporting / Alert Upgrade

목표: 사용자가 봇 상태를 즉시 이해할 수 있게 한다.

구현할 것:

  • live paper dashboard JSON export
  • Research Desk current status 자동 업데이트
  • stage ladder view
  • Strategy Council decision board
  • risk stress view
  • Quant Alert는 mode/fill/risk event 중심
  • heartbeat는 ledger/report에만 저장

Priority Plan

Phase U1 — Observability First

  • ledger schema 정리
  • current stage/TP/next stage/liquidation buffer status export
  • Research Desk Quant status 자동 생성
  • Strategy Council decision schema 작성

Phase U2 — Risk Engine 2.0

  • funding/fee/slippage 누적
  • liquidation/margin approximation 개선
  • gap-down stress runner
  • margin ladder alert/reject 강화

Phase U3 — Scenario + Council

  • context scenario input schema
  • manual context notes ingestion
  • council decision CLI
  • mode switch ledger
  • Research Desk council board

Phase U4 — Replay / Validator

  • paper ledger replay
  • candidate comparison report
  • no-lookahead/OOS checks
  • rejected candidate ledger

Phase U5 — Rust Forecast Core

  • Rust crate scaffold
  • feature parity test
  • CLI forecast output
  • Python integration as advisory guard
