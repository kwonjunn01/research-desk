Strategy Core

Entry

첫 매수는 X × 20 × 0.5 / 31. 현재 2035 USDT 기준 first notional ≈ 656.45 USDT

Ladder

1-2-4-8-16, 총 5단계. 1% 하락마다 다음 stage 1개만 pending

Take Profit

평단 +0.5% 도달 시 전체 익절. TP 미충족이면 사자마자 팔지 않음

핵심 원칙:

  • 원본 보존:
  • 20x fixed display leverage
  • 1-2-4-8-16 5단계 doubling
  • 1% 하락마다 다음 단계 추가매수
  • avg entry +0.5% 전체 익절
  • 변경/보강:
  • 첫 매수 사이즈를 5단계 doubling 전체를 버틸 수 있게 역산
  • pending buy는 다음 stage 1개만 둠
  • stage2~5를 한 번에 전부 미리 깔지 않음
  • Risk Bot은 남은 추가매수만 통제

Add-Buy Gate

게이트는 포지션 청산/익절 로직이 아니라 추가매수 허용 장치다.

ON 조건:

  • ADX < 22
  • Bollinger squeeze lower breakdown 없음
  • margin ratio proxy < 50%

OFF 조건:

  • ADX > 25 and rising
  • Bollinger squeeze lower breakdown
  • margin ratio proxy > 60%

OFF/REST 시 행동:

  • 남은 pending buy 취소 또는 신규 추가매수 중단
  • 이미 보유한 포지션은 계속 보유
  • avg +0.5% TP는 계속 활성
  • 즉시 trailing/split sell 없음

Strategy Council / Regime Switch

전략은 장마다 다르게 켜고 끈다. 단, 그 결정은 단일 지표나 단일 봇이 아니라 Quant Strategy Council의 결정을 따른다.

chart regime + external context + risk state
→ Strategy Council
→ strategy_mode
→ Risk overlay
→ paper/live candidate action

전략 모드:

  • ACTIVE_INFINITE_BUY_V2: 횡보/평균회귀 친화 장세
  • HOLD_EXISTING_NO_NEW_STAGE: 애매한 장세, 기존 TP만 유지
  • ADD_BUY_OFF: 하락추세/브레이크다운 위험, pending buy 취소
  • EVENT_PAUSE: CPI/FOMC/규제/해킹/사회 이슈 등 외부 이벤트
  • DATA_NOT_READY: 데이터 품질 문제

차트만 보지 않고 함께 보는 맥락:

  • macro: FOMC, CPI, 금리, 달러, 유동성
  • crypto structure: funding, basis, OI, ETF flow, liquidation cluster
  • social/geopolitical: 전쟁, 규제, 사회적 panic/risk-off
  • technology/security: chain halt, bridge exploit, custody 이슈
  • exchange health: OKX data stale, mark-last divergence, API timeout

Agent Responsibilities

OKX public data
→ Data Quality Agent
→ Scenario Planning Agent: 외부 맥락/위기 시나리오
→ Strategy Council: 장세별 strategy_mode 결정
→ Strategy Bot: 무한매수법 v2 intent 생성
→ Risk Bot: add-buy gate / margin 방어
→ Paper Broker Agent: paper fill / avg+0.5% TP simulation
→ Ledger
→ Feedback Recorder
→ Validator / Optimizer / Reporting
→ Quant Alert group + Research Desk

운영 원칙:

  • Strategy Bot은 원본 전략 골격을 마음대로 바꾸지 않는다.
  • Risk Bot은 “추가매수 계속/중단”만 우선 통제한다.
  • Optimizer는 후보만 만든다.
  • Validator/Risk가 독립 검증한다.
  • live 승격은 사용자 승인 없이는 불가능하다.
  • 전략 변경은 Strategy Evolution Charter를 통과해야 한다.
